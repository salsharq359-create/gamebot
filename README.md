# جيم بوت (GameBot) — بايثون بالكامل

نفس فكرة خطة Copilot (واجهة + خادم حسابات + خادم ربط فوري)، لكن كل الأجزاء بلغة **بايثون**:

| الجزء | التقنية | المجلد | الدور |
|---|---|---|---|
| الواجهة | Flet | `app/` | تطبيق كمبيوتر وويب (وجوال عبر `flet build`)، بالعربية من اليمين لليسار |
| خادم الحسابات والأرباح | Django | `backend/` | المستخدمون، المنصات، المهام، الأرباح، المستشار، الأمان والخصوصية |
| خادم الربط الفوري | python-socketio | `realtime/` | يشغّل الروبوت ويبث كل حركة مباشرة للتطبيق |
| النشر | Docker + Nginx على AWS EC2 | `deploy/` | HTTPS، وقاعدة PostgreSQL |

فيه فكرتان:

1. **روبوت يلعب** ألعاباً تجريبية داخل التطبيق بخوارزميات حقيقية (BFS، البحث الثنائي، Minimax)، وكل لعبة = 1 دولار.
2. **روبوت مستشار** (فكرة Copilot): تخبره كم دقيقة لديك، فيختار أكثر مجموعة مهام ربحاً من كل ألعابك ومنصاتك
   (حقيبة الظهر 0/1 بالبرمجة الديناميكية)، مع احترام حد اللعب اليومي.

الأرباح والسحب **محاكاة تعليمية**. الروبوت لا يلعب في ألعاب حقيقية ولا يدخل حسابات خارجية: منصاتك الأخرى تضيفها
بنفسك مع مهامها، فيضمّها المستشار إلى خطتك، وتسجّل أرباحها يدوياً.

## التشغيل على جهازك

يحتاج Python 3.11 أو أحدث. افتح ثلاث نوافذ طرفية:

```bash
# 1) Django
cd backend
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver

# 2) خادم الروبوت الفوري
cd realtime
pip install -r requirements.txt
uvicorn realtime.server:app --port 3001

# 3) الواجهة
cd app
pip install -r requirements.txt
python main.py                 # نافذة على الكمبيوتر
flet run --web main.py         # أو في المتصفح
```

على ويندوز استخدم `py` بدل `python` إذا لزم.

## العمل بدون إنترنت وقياسات الشبكة (TM255 - الوحدة 1)

- إذا انقطع الاتصال، يعرض التطبيق أن **يلعب الروبوت على الجهاز** بنفس المحرك (`app/gb/engine/`).
- كل مهمة مكتملة، وكل ربح يدوي، يُحفظ في طابور على الجهاز (`~/.gamebot/queue-<username>.json`) بكتابة ذرية،
  ولكل سجل معرّف فريد.
- كل 15 ثانية يحاول التطبيق إعادة الاتصال وإرسال الطابور دفعة واحدة إلى `POST /api/bot/offline-sync/`.
- الخادم لا يثق بالتطبيق: المبلغ من جدول المهام، والألعاب يجب أن تكون مرتبطة، والحد اليومي يُحسب حسب يوم اللعب،
  والسجلات الأقدم من 7 أيام أو المستقبلية تُرفض، وإعادة الإرسال لا تضاعف الأرباح.
- شاشة **«الشبكة والمزامنة»** تعرض: حالة الخادمين، زمن الاستجابة (REST) وزمن الذهاب والإياب (Socket.io)،
  عدد الطلبات والأخطاء، البيانات المرسلة والمستقبلة، رسم زمن الاستجابة، وحجم آخر مزامنة لكل سجل.
- مفتاح **«وضع عدم الاتصال (للتجربة)»** يقطع الشبكة عن التطبيق لتجربة كل ما سبق بدون فصل الإنترنت فعلاً.

في تجربة فعلية: لعب الروبوت 6 ألعاب بدون اتصال (8$ مع المكافآت)، وعند عودة الاتصال أُرسلت 9 سجلات في 2,319 بايت
(نحو 258 بايت للسجل)، وطابق رصيد الخادم المبلغ.

## كيف تمر البيانات

1. الواجهة تسجّل الدخول في Django وتحصل على رمز موقّع.
2. تتصل بخادم الروبوت عبر Socket.io بنفس الرمز (الخادم يتحقق منه عند Django).
3. عند الضغط على «تشغيل الروبوت»، يلعب الخادم ويبث الحركات والسجل.
4. عند كل مهمة مكتملة، يبلّغ Django بمفتاح داخلي. **Django هو من يحدد المبلغ** من جدول المهام، ويرفض التكرار.
5. يصل الرصيد الجديد للواجهة فوراً، وفي النهاية تُسجَّل مدة الجلسة ويصلك تنبيه.

أحداث Socket.io: `start_bot` · `stop_bot` · `request_bot_suggestion` · `subscribe_platform`، والخادم يرسل
`bot_started` · `bot_event` · `earning` · `bot_done` · `bot_suggestion`. وهي نفس أحداث نسخة Node.js، فتطبيق
Flutter من المشروع السابق يعمل مع هذا الخادم أيضاً.

## تطبيق الهاتف (آيفون و أندرويد)

التطبيق مكتوب بـ Flet، فالكود نفسه يُبنى لأندرويد وآيفون بدون كتابة سطر جديد بلغة أخرى.
لا تعمل العناوين المحلية (`127.0.0.1`) على الهاتف، لذلك يلزم خادم منشور على `https://` (انظر `deploy/AWS-EC2.md`).

```bash
cd app
pip install flet-cli==1.0.3
./build_mobile.sh https://api.yourdomain.com https://api.yourdomain.com apk   # أندرويد: APK
./build_mobile.sh https://api.yourdomain.com https://api.yourdomain.com ipa   # آيفون: macOS + Xcode فقط
```

* السكربت يكتب العناوين في `server.json` ثم يستدعي `flet build`. العنوانان يجب أن يبدآ بـ `https://`.
* أول بناء يحمّل Flutter SDK وأدوات أندرويد (عدة غيغابايتات) ويحتاج اتصالاً بالإنترنت.
* ملف الآيفون يحتاج جهاز macOS مع Xcode وحساب Apple Developer للتوقيع والنشر على App Store.
* غيّر `org` في `app/pyproject.toml` إلى نطاقك (مثل `com.yourname`) قبل النشر، لأن المتاجر ترفض `com.example`.
* قائمة الاستخدام الداخلية (`algorithms`، `tests`) لا تُضاف إلى التطبيق.
* اختبار سريع قبل النشر: ثبّت تطبيق **Flet** من المتجر على هاتفك، ثم شغّل `flet run` من مجلد `app` لترى التطبيق مباشرة على الهاتف.

### البناء عبر GitHub Actions (بدون تثبيت أي شيء على جهازك)

الملف `.github/workflows/mobile.yml`:

1. ارفع المشروع إلى مستودع على GitHub.
2. في **Settings ← Secrets and variables ← Actions ← Variables** أضف `API_URL` و `REALTIME_URL` (بصيغة `https://`).
3. **أندرويد:** يُبنى تلقائياً مع كل دفع إلى `main`. حمّل `gamebot-android` من صفحة التشغيل في تبويب **Actions**، ثم ثبّت ملف APK على الهاتف.
4. **آيفون:** من **Actions ← mobile ← Run workflow**. يُنتج `GameBot-unsigned.ipa` غير موقّع؛ ثبّته بـ Sideloadly وحساب Apple المجاني (التطبيق ينتهي بعد 7 أيام ويُعاد تثبيته).

**ملاحظة:** جرى التحقق هنا من أن `flet build` يتوقف عند تحميل Flutter SDK لأن الحاوية لا تصل إلى مستودعاته، ولم يُنتج ملف APK أو IPA. أما خطوات البناء الكاملة فلم تُجرَ.

## نشر الخادم على Render (مجاناً)

`render.yaml` في جذر المستودع ينشئ **خدمة واحدة** (Django وخادم الروبوت معاً، انظر `deploy/render/combined.py`)
وقاعدة PostgreSQL. العنوان الناتج هو قيمة `API_URL` و `REALTIME_URL` معاً.

1. render.com ← سجّلي الدخول بحساب GitHub.
2. **New ← Blueprint** ← اختاري المستودع `gamebot` ← **Apply**.
3. بعد اكتمال النشر انسخي العنوان من أعلى صفحة الخدمة `gamebot` (مثل `https://gamebot-xxxx.onrender.com`).
4. تحقّقي: افتحي `العنوان/api/health/` في المتصفح، يجب أن يظهر `{"ok": true, ...}`.
5. في GitHub أضيفي المتغيرين `API_URL` و `REALTIME_URL` بهذا العنوان، ثم شغّلي سير العمل `mobile`.

قيود الخطة المجانية: الخدمة تنام بعد 15 دقيقة بلا استخدام وتحتاج نحو دقيقة لتستيقظ (أول تسجيل دخول بعد النوم قد يفشل، أعيدي المحاولة)،
وقاعدة البيانات المجانية **تنتهي بعد 30 يوماً** من إنشائها ثم تُحذف بعد مهلة 14 يوماً إن لم تُرقَّ.
